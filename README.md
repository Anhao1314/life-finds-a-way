## 为什么建立这个仓库

在 AI Coding 中，过度规定实现路线，容易让 AI 把大量时间花在证明一个未经验证的方案“可以实现”，而不是探索用户问题最有效的解法。

这个仓库记录我的长期研发信条：**明确使命，开放路径，守住边界，由真实证据决定哪些改进值得保留。**

它不主张放弃人的责任，也不意味着 AI 可以自行批准资源、权限或高风险操作。自主探索必须与可复现的验证相伴。

## 核心理念

**Life finds a way. Let evidence decide what survives.**

| 原则 | 实践含义 |
| --- | --- |
| **Goal over instructions** | 定义问题、成功条件与价值，不提前锁死技术方案。 |
| **Autonomy within boundaries** | AI 自主研究与实现，但不得自行扩大资源、安全和发布权限。 |
| **Variation → Selection → Retention** | 提出备选路径，以实验筛选，保留有效改进。 |
| **Falsify early** | 优先开展低成本、能否定假设的实验。 |
| **Evidence over performance theater** | 保留 FAIL、BLOCKED、INCONCLUSIVE，不以代码量和漂亮演示冒充能力增长。 |
| **Humans remain accountable** | 人负责使命、约束和最终选择；AI 负责探索、实施与提出异议。 |

## 从这里开始

阅读 **[完整研发宪章 CHARTER.md](./CHARTER.md)**。

这份宪章适用于 FlowCredit、具身智能、Agent Runtime、个人 AI Coding 等场景，但不绑定任何特定模型、框架或工程仓库。

未来给 Coding Agent 下达任务时，优先使用以下五个要素：

> **使命**：真正要解决什么问题？  
> **现状**：已核验的基线与失败是什么？  
> **资源**：时间、算力、工具和额度有多少？  
> **边界**：哪些操作需要额外授权？  
> **验收**：如何证明能力确实变好了？
>
> 允许 Agent 自己寻找道路，以最小实验验证方案；不因既定计划而执着于错误路径。

完整的可复制任务模板见宪章第六节。

宪章可以随实践而演进，但每项重要修订都应回答：**哪次真实经历促成了修改？具体改变了什么？什么证据支持这次改变？**
