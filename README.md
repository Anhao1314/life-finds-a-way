## The Journey

*这不是一个从一开始就正确的故事。它来自我在 AI Coding 中走过的弯路。*

### 01 / 我曾以为，Prompt 越详细，结果就越可靠

一段时间里，我习惯先替 AI 设计好系统：选框架、画架构、拆模块、规定执行顺序，再要求它逐项完成。我把自己放在指挥每一步的位置，仿佛只要计划足够周密，剩下的就是执行问题。

这确实能产出代码，也能让许多局部测试通过。但我后来发现：**我在提问时，常常已经把一个未经验证的解决方案，伪装成了任务本身。**

AI 认真执行的是我指定的路径，不一定是解决问题最值得走的路径。

### 02 / 代码越来越多，真正的问题却不一定更近

我在做 Agent、金融研究工具、机器人 Runtime 和各种 AI Coding 实验时，反复遇到一种熟悉的节奏：

一个任务要做很久；一次只推进一小段；随后开始处理依赖、接口、权限、测试环境、工作流和其他工程性问题。解决一个问题，又出现更多需要修复的环节。

这些工程工作并非没有意义。有些是在守住安全与可靠性的底线。但当我只问“下一步该修什么”，而不问“我们为什么还在走这条路”，就容易把**维持当前方案**误认为**接近真正目标**。

我开始怀疑：让我疲惫的，未必只是模型不够聪明，也可能是我给它安排了太多“应该怎样做”，却没有给它足够空间判断“到底值不值得这样做”。

### 03 / 几次真实结果，推翻了我对「进步」的直觉

我不想用一段漂亮的成功叙事抹掉这些记录。

- **[Deep Native](https://github.com/Anhao1314/deep-native)**：我尝试用 Skill、额外验证和工作流约束改善 Coding Agent。但 v0.1 的 10 组完整配对里，Raw DeepSeek 完成 **8/10**，启用 Deep Native 后完成 **7/10**；工具调用中位数从 **29** 增至 **36**。更多步骤并没有在这次小规模实验中换来更多任务胜利。它不足以证明 Skill 一定无效，却足以让我停止把“流程更完整”直接等同于“效果更好”。[查看保留的实验结果](https://github.com/Anhao1314/deep-native/blob/main/docs/v0.1-pilot-findings.md)。
- **[G1 具身智能研究](https://github.com/Anhao1314/g1-jev-swarm-lab)**：我学会了不能为了获得 PASS 改写严格评分。一次已见状态、固定种子下的成功，只能支持有边界的结论；任务严格失败、授权拒绝和未证明的可靠性也必须被记录。**让实验说“不”，比让报告看起来成功更重要。** [查看负面结果与研究边界](https://github.com/Anhao1314/g1-jev-swarm-lab/blob/main/docs/lab-notebook/negative-results.md)。
- **[FlowCredit](https://github.com/Anhao1314/flowcredit-research)**：随着 Agent、研究工作流和证据系统不断演进，我越来越不能用“报告生成了”“工程跑通了”来代替真实用户价值。瓶颈可能在模型，也可能在数据、工具、授权或交互。**继续增加模型能力或系统复杂度，不应该成为默认答案。**

这些项目的问题不同，教给我的却是同一件事：**工作量不等于能力增长；工程上的 PASS 不自动等于真实世界里的成功。**

### 04 / 转折：我是不是一直在教 AI「怎么做」？

真正改变我思路的，是把问题反过来问：

> **为什么我总是把一个已经想好的方案交给 AI，让它努力实现，却很少允许它先判断：这是不是解决问题最好的路？**

以前，我常常是**先选道路，再要求 AI 证明这条道路走得通**。

现在，我想尝试的是：**先定义值得抵达的目标、现实边界和验收标准，再允许 AI 自己探索道路；让实验，而不是我对某种架构的偏好，决定哪些改变值得留下。**

这不意味着我从此不参与技术设计。设计仍然重要，只是需要分清：哪些约束真的不可改变，哪些只是尚未被证明的个人假设。

### 05 / 2026.10.13：生命会寻求自己的出路

我最终用 **Life Finds a Way** 来命名这次认知转变。

生命不会等待一份完美的施工图才开始寻找出路。不同可能性出现，在环境中受到检验；一些道路走不通，一些得以延续。对 AI Coding 而言，这给了我一个启发：

**人类不必预先规划每一段路径，但必须清楚为什么出发、资源边界在哪里，以及凭什么判定一条路真的更好。**

我借用的是 **Variation → Selection → Retention（变异 → 选择 → 保留）** 这一探索与选择的机制，而不是声称 AI 已经具有生命，也不是相信只要放手，它就必然能找到正确答案。

> **我负责提出值得解决的问题，AI 负责探索可能的道路，真实世界负责给出反馈。**
>
> **Life finds a way. Let evidence decide what survives.**

这就是这份研发宪章的起点。它不是我已经证明的终极方法，而是我愿意在未来项目里不断接受挑战、修正甚至推翻的工作假设。

## The Loop · 让探索带来可验证的进步

<div align="center">

**MISSION → VARIATION → FALSIFICATION → SELECTION → RETENTION**

*定义使命 → 探索路径 → 最小证伪实验 → 证据判断 → 保留有效改进*

</div>

| 环节 | 实际要做的事 |
| :-- | :-- |
| **01 · Frame** | 先核对真实问题、已有基线、预算和不可越过的边界。 |
| **02 · Explore** | 让 AI 比较有意义的替代路径，包括复用现有能力、简化方案或暂时不做。 |
| **03 · Falsify** | 优先进行能区分假设的最小实验，而不是只做一个好看的演示。 |
| **04 · Decide** | 保留有效改变；证据不足则标记未知；无效时换路、回退或停止。 |

`PASS`、`FAIL`、`BLOCKED`、`INCONCLUSIVE` 和 `NOT_PROVEN` 都可以是诚实的结论。保留原始证据，不修改历史 Gold、阈值或失败记录来制造进步。

## The Rules · 我现在坚持的边界

- **Goal over instructions.** 清晰地定义问题和验收，不把偏好的技术路线伪装成必选项。
- **Autonomy within boundaries.** AI 可以选择方法，但不能自行扩大权限、预算或高风险操作范围。
- **Falsify early.** 对不确定的方向，先用小实验尝试证明自己错了。
- **Evidence over theater.** 更多代码、Agent、工具调用和通过的局部测试，不自动构成能力提升。
- **Humans remain accountable.** 人负责使命、风险、资源与最终批准；AI 的自我评价不能替代独立验证。

**这不是所有任务都必须遵守的繁琐仪式。** 简单问题用简单办法解决；只有不确定性、成本和风险增加时，才增加实验与审查强度。

## Model Scope · 当前的模型适用边界

**现阶段，我只将这套“明确目标、开放路径、由证据选择”的 AI Coding 方法用于擅长高阶推理的模型**，例如 **GPT-6 Astra**、**Claude 的高级推理模型**等。

因为我减少了对实现步骤的预先规定，模型就必须承担更多判断：理解真实目标、识别错误前提、比较不同路径、设计能够证伪假设的实验，并在遇到失败或证据不足时主动换路、停止或报告 `INCONCLUSIVE`。**能写代码，不等于能可靠地自主选路。**

这是我**当前的使用限制，而不是已经证明的模型能力分界线**。我尚未完成跨模型、同条件的充分对照实验，也不认为使用高级模型就自动保证成功。对于轻量模型或高阶规划能力不足的配置，我暂不直接套用这种高自主、低指令密度的方法；应当缩小任务范围、明确必要步骤、加强人工审查和独立验证。

未来如果真实实验支持扩大适用范围，我会据此修订，而不会把今天的模型选择当作永恒规则。

## Quickstart

把下面的任务定义交给 Coding Agent。**明确终点，而不是提前给出完整施工图。**

~~~text
使命：[真正要解决的用户问题，以及成功时可观察到的变化]
现状：[已核验的系统基线、已有资产、已知失败]
资源：[可用时间、工具、算力、预算]
边界：[不可修改的证据、禁止操作、需另行授权的事项]
验收：[怎样比较、复现和判断结果]

请先核对真实瓶颈，再自主研究可行路径。
允许质疑我的初始方案，优先复用已有资产并进行最小判别实验。
在已授权范围内推进，不得自行扩大资源、权限或不可逆操作。
最后报告真实结果、失败与未知、成本，以及接受/换路/停止的建议。
~~~
