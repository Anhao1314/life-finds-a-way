# 设计语言

这份文档解释 `index.html` 与 `assets/` 里的视觉是怎么来的。它不是风格偏好清单，而是一组**可测量的约束**——
凡是能被脚本生成的，就不应该放进仓库；凡是不该出现在画面里的，就不应该被顺手加进来。

> 设计语言的参照对象是月之暗面招聘官网（careers.kimi.com）的 1-bit 像素体系；
> 但隐喻没有照搬：本仓库自己的内核是「变异 → 选择 → 保留」，
> 所以母题是**分支与证据之光**，而不是登月。

---

## 一、颜色：只有两种，灰由网点表达

| 用途 | 值 |
| --- | --- |
| 底 | `#000` |
| 墨 | `#fff` |
| 次级信息 | `#7a7a7a`（唯一的灰） |
| 分割线 / 轨道 | `#4f4f4f` |

**画面里不允许出现第四种颜色。** 所有"灰阶"都是 Bayer 8×8 有序抖动（ordered dither）的结果：
一个 0.46 的场值经过抖动后被画成约 46% 的网点，看上去是灰，本质仍是黑与白两色像素。

极少数需要"压暗"的地方（首屏文案下方的蒙版）用半透明黑渐变，属于功能性处理，不引入新颜色。

## 二、字体：一种像素字，层级只靠字号

- 唯一字体：**Fusion Pixel 12px Mono zh_hans**（[上游](https://github.com/TakWolf/fusion-pixel-font)，SIL OFL 1.1）。
- 只有字重 **400**。所有层级差异由字号承担：`14 / 15 / 16 / 20 / 22 / 24 / 64px`。
- 字号一律用 `clamp()` 限定，避免在超宽屏上失去像素感：
  `--title: clamp(28px, min(7.4vw, 64px), 64px)`。
- 大字标题带**硬阴影**，不带模糊：`text-shadow: -4px 6px 0 #000`。
  像素风格里没有柔光，只有位移。
- CJK 标题反而加字距：`letter-spacing: .64px`。
- 图像一律 `image-rendering: pixelated`；图标用 SVG 作 **CSS mask** 上色
  （`assets/site/mark.svg`、`icon-swipe.svg`），因此一个形状可以随状态换色，而不必准备多份文件。

字体不进仓库的原始版本（4.6 MB），而是由 `tools/build_font.py` 扫描页面用到的字符后子集化：
输出 `assets/fonts/lfaw-pixel-mono-subset.woff2`（约 15 KB）。
子集属于修改版本，按 OFL 不沿用原字体名，页面中的 family 名为 `LFAW Pixel`。

## 三、美术：全部由脚本生成

`tools/make_art.py` 用确定性算法绘制所有图形，Bayer 8×8 抖动量化到 1-bit，再按整数倍（×4）放大：

| 产物 | 尺寸 | 用途 |
| --- | --- | --- |
| `assets/hero-banner-dark.png` / `-light` | 888×414 | README 主视觉：中文标题与英文锁排都烧进图里 |
| `assets/evidence-dark.png` / `-light` | 888×309 | README 证据板：三列数字与状态 |
| `assets/divider-dark.png` / `-light` | 888×48 | README 章节分隔带 |
| `assets/loop-dark.png` / `loop-light.png` | 888×417 | README 的闭环示意图 |
| `assets/media/journey.gif` | 640×360 · 92 帧 · 12 fps | README 的动效演示，约 0.45 MB |
| `assets/site/hero.png` | 1280×720 | 站点首屏背景（不含文字） |
| `assets/site/fork.png` | 1280×720 | 提问的方式：一条路分岔，左暗右亮 |
| `assets/site/boundary.png` | 1280×720 | 自主的边界：顶部许可区、一条边界虚线、越线尝试到线即止 |
| `assets/site/loop-glow.png` | 1280×720 | 闭环：贴着轨道的环状辉光 |
| `assets/site/step-{vary,select,retain}.png` | 120×120 | 三站的像素图标：分叉 / 漏斗落点 / 盆里的芽 |
| `assets/site/nebula.png` | 1280×720 | 结尾场景的抖动星云 |
| `assets/site/evidence-wall.png` | 1280×720 | 证据墙：状态记号组成的纹理（站点内压到 0.22 不透明度） |
| `assets/site/ring.png` | 600×300 | 闭环的虚线轨道 |

三个母题：

1. **分支**——多条道路同时存在，绝大多数保持暗淡（0.42~0.56 的网点）。
2. **证据**——一道窄光带斜穿画面。只有被照到的那条路是**实心**的（场值 1.0）。
3. **保留**——被照亮的路径尽头，长出一颗小小的芽（`sprout()`）。

绘制顺序有讲究：**先光带与雾，再给每条路"凿"出暗槽（`carve()` 乘法压暗），最后落线。**
不振槽的话，虚线路会被亮区吞掉——这是从实际渲染里看出来的，不是想出来的。

**输出宽度必须等于显示宽度（1:1 出图）。**
1-bit 网点经非整数缩放必然糊掉：第一版 README 图按 1200px 出图，被 GitHub 的栏目（约 888px）压到
0.74 倍，3px 网点变成 2.2px 的糊斑；动图更被缩到 0.5625 倍。修正后：
README 位图按 296 逻辑像素 ×3 = 888px 出图（与栏目宽一致），`<img width="888">`；
动图从 1280×720 的帧按整数倍最近邻缩到 640×360（每点恰好 2px），绝不用 LANCZOS。
逻辑画布改窄后构图要重排：暗池、椭圆半径、标签位置都是跟着画布尺寸反推的，不是挪一挪就行。

还有一条更硬的规则：**美术必须避让文字带。**
`content_band()` 把场景中段（纵向 20%~82%，边界用 smoothstep 过渡）的场值按比例压暗，
所以密度冲突是在生成阶段解决的，而不是事后拿 CSS 蒙版去盖。

配套的取值纪律：`#7a7a7a` 只适用于近黑底。一旦某个场景铺了美术，
次级文字要提亮一档（本站用 `#a0a0a0`）——否则网点会把灰字吃掉。
证据墙这类"文字纹理"尤其危险：它本身是字，密度必须压到 0.22 不透明度以下，
并加中心暗角，否则它会和正文抢注意力。

## 四、动效：一个缓动函数，两种扫光

| 场景 | 参数 |
| --- | --- |
| 全站缓动基准 | `cubic-bezier(.16, 1, .3, 1)`（easeOutExpo 系） |
| 交互态过渡 | `.2s cubic-bezier(.4, 0, .2, 1)` |
| 场景切换 | `.5s` 交叉淡入；文案离场向 `-12px` 收起 |
| 入场错峰 | `.6s`，每元素延迟 `calc(var(--i) * 90ms)` |
| 计数滚动 | 900~1200ms，三次贝塞尔缓出 |

**光带扫字**（每个场景底部的提示）是本设计唯一的标志性动作，实现方式是**同一份内容画两遍**：

- 底层用 `--dim` 画一遍；
- 上层用 `--ink` 再画一遍，只让一条 116px 高的渐变带经过的地方显形：
  `mask-image: linear-gradient(transparent 0, transparent 38%, #000 50%, transparent 62%, transparent 100%)`
- 动画只改 `mask-position`，于是光自上而下扫过文字。

**行程要按框高算，不能凭感觉给。** 亮带位于 116px 遮罩的 38%~62%（即 44~72px 处），
而提示框只有 52px 高，所以行程必须覆盖「带底贴框顶」到「带顶贴框底」，即 **-84px → 58px**。
第一版写成了 `-150px → 210px`，光带三分之二的时间在框外空转，扫光几乎看不见——
这是靠逐像素测量（遮罩不同位置下提示区的最亮值）才发现的，不是看出来的。

**逐字翻牌**（顶栏）：每个字被包进固定高度的窗口（`overflow: hidden`），
内部叠放同一字形的两份，悬停时整列上移一行再瞬间复位——因为两份字形相同，复位不可见，读起来就是字符在持续滚动。

## 五、交互：滚动即推镜头

- 页面**不能原生滚动**（`#stage` 为 `height: 100svh; overflow: hidden`），一次只显示一个场景。
- 滚动、触摸、方向键、数字键 `1–7` 都可切换场景；`#s1…#s6` 支持深链接。
- 结尾的星云随"余量滑动"缓慢位移（`--closing-progress`），给结局留出呼吸的余地。
- 顶栏固定在所有场景之上，当前场景高亮为白底黑字。
- **放不下的场景内部可滚动**：窄屏或矮屏时，面板先自己滚到底，再滚动才翻页
  （`scrollHostOf()` 判断 `scrollHeight > clientHeight`）。宁可让内容多滚 221px，也不裁掉一段证据。
- `prefers-reduced-motion` 下：所有动画时长归零、扫光层隐藏、内容直接呈现。
- **无 JS 时**（`html.no-js`）场景退化为普通文档流，内容仍然完整可读。

## 六、动图怎么来的

GitHub 的 markdown 装不下字体、CSS 与 JS——**README 里能承载动效的形式只有动图**。

- 拍摄：把动画进度变成可设定的参数（`animation: none` + 直接写 `mask-position` / `offset-distance` /
  `opacity`），逐帧设定状态再截图，因此帧与帧之间的时间完全可控，不受截图延迟影响。
  帧序列不入库（`frames/` 在 `.build/` 下）。
- 合成：`tools/make_gif.py` 把每帧按**整数倍最近邻**缩放（1280→640，每点恰好 2px），
  再量化到同一组固定色（黑、白、四档灰）。不用 LANCZOS——它会把网点糊成雾；
  不用自适应调色板——否则帧间调色板漂移会闪，而且 LZW 压缩更差。
- 结果：8.5 秒 / 640×360 / 12 fps 的 GIF 只有约 0.45 MB，因为画面本身就是 1-bit 的。

## 七、内容纪律

排版可以重构，**结论不能改写**。这一版只动了展示层：

- 数字、分数、状态、限制条件原样保留（`8/10`、`7/10`、`29 → 36`、`INCONCLUSIVE`…）。
- 不确定的地方照旧写成不确定（"小样本不能否定所有技能"、"不是已经被对照实验确认的分界线"）。
- 页脚标注了出处：美术由脚本生成、字体的许可证位置、以及"文档内容未作改动"。

这一条比任何视觉规则都重要：**一份讲证据的文档，不能靠展示层把自己讲得比证据更漂亮。**
